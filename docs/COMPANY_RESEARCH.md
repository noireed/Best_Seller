# 기업 귀속·공시 원문·재무 해석·사건 이력

## 실행

```bash
python -m app.company_cli --symbol 035420 --output data/company_035420.json
python -m app.company_cli --fixture examples/company_event_history.json --output data/history_demo.json
```

첫 번째 명령은 설정된 뉴스와 DART를 조회해 기업 분석 자료를 만듭니다. 팀 로그인, LLM 호출이나 주문은 하지 않습니다. 두 번째 명령은 외부 호출 없이 합성 사건의 최초 보도 → 수치 충돌 → 정정 후 상태를 재현합니다. 실제 거래 반복 실행에서는 같은 분석을 기존 판단 경로에 연결합니다.

```dotenv
EVENT_HISTORY_ENABLED=true
DART_DOCUMENT_ENABLED=true
FUNDAMENTAL_GUARD_ENABLED=true
```

기존 `.env`의 뉴스·DART 키를 그대로 사용합니다. 공시 원문과 기사, 캐시, 분석 결과는 `data/`에 보관하고 공개 저장소에 올리지 않습니다.

## 기업 귀속

회사명이 등장하는 절에서 사건 표현 앞뒤의 위치와 관계 표현을 확인합니다.

| 제목 형태 | 처리 |
|---|---|
| 삼성전자 영업이익 20% 증가 | 직접 사건 후보 |
| 삼성전자 협력사 영업이익 20% 증가 | 협력사 사건으로 제외 |
| Samsung Display revenue grew 10% | 짧은 Samsung 별칭으로 삼성전자에 귀속하지 않음 |
| Apple wins contract from Samsung Electronics | 삼성전자는 거래 상대방이므로 직접 수주로 처리하지 않음 |
| Samsung Electronics wins contract with Apple | 삼성전자가 사건 앞 주체인 직접 수주 후보 |
| 삼성전자와 애플 영업이익 증가 | 복수 주체가 불명확하므로 제외 |

직접 귀속 사건만 `events`에 남기고 나머지는 `rejected_events`에 상태와 이유를 남깁니다. 문구·사건·기업 언급의 위치는 원문 제목을 기준으로 추적할 수 있습니다. 제외된 기업 사건은 직접 점수 및 LLM 뉴스 입력에서 차단합니다. 직접 사건과 다른 기업 사건이 한 기사에 섞이면 LLM 입력에서는 기사 전체를 제외합니다.

규칙 기반의 보수적 판정입니다. 이름 목록은 기업 언급을 구분하기 위한 것이며 현재 지분 관계나 경쟁 관계를 증명하지 않습니다. 목록에 없는 기업·복잡한 관계절·생략된 주어를 모두 해결하지 못하므로 완전한 기업 관계 추출 모델로 해석하지 않습니다.

## 공시 원문 자동 수집

종목코드 → DART 회사 고유번호 → 최신 지원 정기보고서 → 연결재무제표와 원문 ZIP을 찾습니다. 원문에서 사업 설명·위험관리·재무 설명에 해당하는 문단을 제한적으로 추출합니다. 문단마다 파일명·제목·출처 접수번호·URL·해시를 남깁니다.

원문에 이스케이프되지 않은 `R&D` 같은 표현이 있으면 외부 엔터티를 해석하지 않는 관대한 마크업 파서를 사용하고 그 사실을 기록합니다. 파일 크기와 문단 수를 제한하며 XML 엔터티 선언은 거부합니다. 원문 형식만 지원하지 못한 경우 구조화된 재무정보 조회까지 중단시키지 않습니다.

문단은 발행 기업의 설명입니다. 위험 단어를 세거나 문단의 긍정·부정 표현만으로 매매 점수를 주지 않습니다. 재무 수치는 원문 표를 임의 해석하지 않고 구조화된 재무제표에서 계산합니다. 공시 본문에 있는 지시문을 LLM에 전달하지 않습니다.

공식 명세: [공시서류원본파일](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003).

## 재무 흐름과 판단

기존 매출·영업이익·영업이익률에 유동자산·유동부채·부채·자본·영업현금흐름을 추가합니다. 지원하는 표준 계정이 하나이고 원화일 때만 계산하며, 누락값을 0으로 바꾸지 않습니다.

- 유동비율 = 유동자산 / 유동부채
- 부채/자본 비율 = 부채 / 자본. 자본이 0 이하이면 비율을 계산하지 않음
- 영업현금흐름은 분기 독립 값이 아니라 누적 값으로 명시
- 매출 증가와 영업이익 감소, 영업손실, 이익률 하락, 자본 0 이하, 누적 영업현금흐름 음수 등을 사실·주의 항목으로 분리

지표의 해석은 업종·계절성·투자 단계에 따라 달라질 수 있습니다. 부채비율이나 현금흐름의 부호만으로 매수·매도를 확정하지 않습니다.

현재 판단에 연결한 규칙은 제한적입니다. 연결 기준과 연도·회계기간·전년 동기 비교가 모두 맞는 긍정적 매출·영업이익 기사에서, 해당 재무제표에 매출 증가·이익 감소 또는 영업손실이 있으면 기사 기여를 0.5배로 줄입니다. 계약·배당이나 다른 기간의 뉴스에는 적용하지 않고 부정 점수를 뒤집거나 새 매수 점수를 만들지 않습니다. 누적 뉴스는 분기 독립 수치와 혼합하지 않도록 감쇠 대상에서 제외합니다.

0.5는 실험적인 고정 규칙이며 수익률로 검증된 최적값이 아닙니다. 해당 기사는 재무 문맥 없이 LLM으로 우회 반영되지 않도록 LLM 뉴스 입력에서도 제외합니다. `FUNDAMENTAL_GUARD_ENABLED=false`로 감쇠만 비활성화할 수 있습니다.

## 사건 이력과 시점

SQLite `economic_event_history`에 기사 URL·발행 시각·처음 관측한 시각·기업 귀속·사건·원문 근거를 기록합니다. 같은 관측을 반복 저장하지 않으며 프로그램 재실행 후에도 유지합니다. 원문 보도를 삭제하거나 덮어쓰지 않습니다.

기업·지표·연도·분기/연간·연결 기준·전년/전분기 비교·누적 여부가 명확히 같은 수치 사건만 기사 사이에서 연결합니다. 식별 근거가 부족한 계약·화재 등은 제목이 비슷해도 같은 사건으로 합치지 않습니다.

- 동일 발행처의 명시적 정정은 이전 수치의 기여를 제거합니다.
- 같은 범위에서 1%p를 넘는 수치 충돌이 남으면 그 그룹을 보류합니다. 어느 언론사가 옳은지 자동 확정하지 않습니다.
- 같은 수치에 나중 부인·철회가 있으면 이전 기여를 제거하며, 부인된 수치의 단순 재보도로 되살리지 않습니다.
- 같은 수치의 재보도는 최초 보도의 나이를 유지합니다. 최초 보도가 분석 유효기간을 벗어나면 새 제목으로 재등장해도 점수를 주지 않습니다.
- 발행 시각과 관측 시각이 모두 판단 시점 이하인 기록만 사용합니다. 미래 정정은 과거 판단에 영향을 주지 않습니다.

이 연결은 공통 인과관계나 기사 사실을 증명하지 않습니다. 복잡한 사건의 연결·해제에는 별도 검토가 필요합니다. 관측 자료가 10,000건을 넘는 스냅샷은 일부만 사용하지 않고 이력 사용 불가로 표시합니다. 이력 저장에 실패하면 기존 판단을 유지하며 상태를 기록합니다.

연구용 기능별 비교와 기사 제거 실험에는 기록된 이력 스냅샷과 재무 설정을 함께 적용합니다. 따라서 기사 제거 실험도 고정된 과거 이력 아래의 입력 민감도이며, 해당 기사가 세상에 없었을 때의 시장 효과를 뜻하지 않습니다.
