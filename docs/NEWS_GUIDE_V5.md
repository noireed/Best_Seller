# 뉴스 API와 경제사건 판단 모듈

## 기능 범위

뉴스 데이터 수집·품질 관리와 경제사건 기반 매매 보조지표를 제공합니다.
기존 가격 지표·거래 API와 연결하되, 뉴스 입력부터 평가·설명까지 독립적으로 실행할 수 있습니다.

## 실제 구현한 내용

| 분야 | 구현 | 프로젝트에 필요한 이유 |
|---|---|---|
| 뉴스 API | GNews 응답을 공통 기사 형식으로 변환 | 거래 서버에 없는 뉴스 입력을 보충합니다 |
| 호출 관리 | SQLite 영속 캐시, UTC 일일 예산, 요청 간격, 오류 후 중지 | 재실행·동시 실행으로 무료 한도를 낭비하는 일을 줄입니다 |
| 품질 검사 | 종목 관련성, 시각, 지연, 중복, 출처 그룹 검사 | 무관하거나 뒤늦은 기사가 점수에 섞이는 것을 줄입니다 |
| 경제사건 | 이익·매출·계약·주주환원·운영 위험 구분 | 단순 긍정/부정 대신 어떤 사업 지표와 관련되는지 남깁니다 |
| 수치 보존 | 제목에 나온 매출 변화율의 값·단위·방향·비교 기준 추출 | 매출 증가율을 이익 증가율이나 기대 주가수익률로 잘못 바꾸지 않습니다 |
| 판단 연결 | 제한된 뉴스 점수로 기존 BUY/SELL/HOLD 보조 | 뉴스 반영 전후의 결정과 반영되지 않은 이유를 기록합니다 |
| 설명 | 특정 기사를 제외했을 때 판단 재계산 | 어느 근거가 출처 조건이나 임계값을 바꿨는지 확인합니다 |
| 평가 | 라벨 데이터의 혼동행렬, precision/recall/F1, 오답 목록 | 시연 성공과 실제 분류 성능을 구분하고 빈틈을 찾습니다 |

## 파일 구성

- `app/news.py`: 공급원 어댑터, 공통 기사, 기본 필터와 공급원별 상태입니다.
- `app/news_transport.py`: API 캐시·예산·호출 간격·쿨다운·상태 조회입니다.
- `app/economic_news.py`: 회사별 경제사건·시간 감쇠·발표 수치 추출입니다.
- `app/decision_policy.py`: 뉴스 반영 전후의 판단과 반영/제외 이유입니다.
- `app/news_explain.py`: 동일 입력에서 기사를 제거하는 민감도 분석입니다.
- `app/news_evaluation.py`, `examples/economic_labels.json`: 평가 도구와 합성 진단 예문입니다.
- `app/engine.py`, `app/storage.py`: 기존 매매 결정 경로 연결 및 감사 기록입니다.

## API 관리의 정확한 범위

GNews 공식 무료 조건은 하루 100회·요청당 최대 10건·12시간 지연입니다.
로컬 예산 기본값은 하루 80회로 두어 수동 점검 여유를 남깁니다. 하루 기준은 UTC이며 한국 시각 오전 9시에 바뀝니다.

캐시와 예산은 같은 API 키와 같은 SQLite 파일을 사용하는 실행 사이에서 유지됩니다.
요청 전에 트랜잭션으로 예산을 예약하므로 여러 프로세스가 동시에 예산을 넘기지 못하게 합니다.
단, 별도 컴퓨터·다른 DB·외부 프로그램의 호출은 집계하지 못하므로 서버의 사용량과 같지는 않습니다.
설치 이전 호출량도 자동 복원하지 않습니다. 불명확한 요청이나 실패 요청의 로컬 예약은 돌려주지 않습니다.

유효한 캐시가 있으면 네트워크 호출을 하지 않으며, 최초 수집 시각도 유지합니다.
만료한 캐시는 API 장애 때 판단 근거로 재사용하지 않습니다.
403은 다음 UTC 날짜까지, 401은 기본 1시간, 429/서버·통신 오류는 기본 60초간 새 요청을 중지합니다.
Retry-After가 있으면 더 긴 대기 시간을 반영합니다. 그 자리에서 자동으로 반복 요청하지 않습니다.
요청 메타데이터에는 원문 API 키나 요청 URL을 저장하지 않습니다.

공식 조건: https://gnews.io/faq
오류 정의: https://docs.gnews.io/error-handling

## 경제지표가 의미하는 것

예를 들어 `Samsung Electronics sales fell 7 percent year-on-year`에서는
metric=revenue, value=7, unit=percent, direction=decrease, comparison_basis=year_on_year를 기록합니다.
이는 “그 제목이 그렇게 보도했다”는 추출 결과이며 실제 공시의 사실 확인은 아닙니다.
비교 기준이 없는 제목에는 unspecified를 남깁니다. 숫자가 크다고 주문 비중을 자동 확대하지 않습니다.

전망·부인·혼합 감성은 점수를 보류하며, `avoids recall`처럼 악재를 피했다는 일부 표현도 중립 처리합니다.
자연어 표현을 모두 이해하는 모델은 아닙니다. 매출/이익/현금/주가수익률은 서로 다른 값으로 다룹니다.
네이버 API는 현행 이용 조건 때문에 분석 경로에서 제외한 v4 방침을 유지합니다.

## 평가 결과와 한계

초기 합성 진단 예문은 20건 중 18건을 맞혔습니다. 오답을 확인한 뒤 수치 변화 표현과 일부 부정 문맥을 보완했습니다.
추가한 예문을 포함한 현재 진단 자료는 **합성 24건, 정답 22건, 정확도 약 91.7%, macro-F1 약 0.933**입니다.
수요 회복(`demand rebounds`)과 마진 압박(`margin compression`) 예문은 아직 놓칩니다. 오답을 평가 결과에서 숨기지 않습니다.
두 버전의 예문 구성이 다르므로 이 수치를 90%에서 91.7%로 개선된 독립 실험이라고 해석하지 않습니다.

이 데이터는 개발자가 작성한 진단 예문이며 학습/검증 분리된 실제 뉴스 데이터가 아닙니다.
실제 성능을 말하려면 팀원이 별도 뉴스 표본에 라벨을 붙여 같은 도구로 평가해야 합니다.
거래 수익률·초과성과·손실 회피 효과는 검증하지 않았습니다.

기사 제거 시연에서는 두 출처 중 하나를 빼면 출처 조건이 깨져 BUY가 HOLD로 돌아오는 모습을 확인합니다.
이는 규칙의 입력 민감도이며 그 기사가 실제 주가를 움직였다는 인과관계가 아닙니다.
뉴스를 읽은 LLM의 점수를 다시 생성하지 않고 재계산한 것처럼 표현하지 않습니다.

## 실행 예시

1. API 상태: `python -m app.news_cli --api-status` — 외부 호출 없이 로컬 예산·캐시·쿨다운을 보여줍니다.
2. 평가: `python -m app.news_evaluation --output data/evaluation.json` — 분류 결과·오답·기사 제거 민감도를 보여줍니다.
3. 판단 변화: `python -m app.strategy_demo` — 긍정/부정/불확실한 뉴스가 판단을 어떻게 바꾸는지 보여줍니다.
4. 실제 수집: `python -m app.news_cli --provider gnews --symbol 005930` — 조건에 맞는 기사가 없으면 empty로 남는 것도 설명합니다.

이 시연에는 AQuA 주문 권한이나 LLM 키가 필요 없습니다. 마지막 명령만 뉴스 API를 호출할 수 있습니다.
팀 자산·시세를 결합한 검증에는 별도로 AQuA TEAM_CODE를 설정해야 합니다.
