# 뉴스 경제사건 판단 규칙

## 범위와 현재 상태

Best_Seller의 가격 지표에 뉴스 경제사건을 반영하는 판단 규칙입니다.

뉴스 API 응답 성공과 AQuA 거래 환경 준비는 다릅니다. 팀 자산·시세 조회에는 AQuA TEAM_CODE가 필요하며
OPENAI_API_KEY는 선택입니다. 검증 중에는 DRY_RUN=true, ENABLE_TRADING=false를 유지합니다.

## 원본에서 변경한 지점

원본은 기술 점수 70% + LLM 점수 30%, 임계값 ±0.35였습니다.
키가 없으면 LLM 신뢰도가 0이 되어 BUY 수량이 0이었고, 뉴스는 경제 지표로 계산하지 않았습니다.

새 정책에서는 다음 순서로 계산합니다.

1. 최소 55봉의 유효한 가격 이력과 현재 시각을 확인합니다. 부족/중복/비정상/미래 시각이면 HOLD입니다. 마지막 봉이 7일 넘게 오래되어도 HOLD입니다.
2. EMA·RSI·모멘텀을 계산합니다. 손실이 0인 상승 구간 RSI=100, 완전 횡보 RSI=50 처리를 보완했습니다.
3. 기존 LLM이 실제로 사용 가능하고 신뢰도 조건을 충족하면 기술 80% + LLM 20%를 기준 점수로 계산합니다. 없으면 기술 점수를 기준으로 삼습니다. 이 비중은 실험 설정이지 최적화 결과가 아닙니다.
4. 뉴스 경제사건 점수로 최대 ±0.15 범위의 조정을 더합니다. 실제 값은 사건 강도·기사 나이·공급 지연 때문에 대체로 더 작습니다.
5. 최종 점수가 +0.35 이상이고 기술 점수도 +0.2 이상이면 BUY, -0.35 이하이고 기술 점수도 -0.2 이하이면 SELL, 나머지는 HOLD입니다.
6. 가용 현금·주식·비중·수수료를 반영해 수량을 정하고, 독립된 위험검사와 실행 모드를 확인합니다.

뉴스만으로 가격 추세 반대 방향의 주문을 만들지 않습니다. 뉴스 장애/무관 기사/근거 부족에서는
뉴스 조정이 0이며 기술(+선택적 LLM) 판단이 유지됩니다. 이는 “정보가 부족하니 무조건 안전하다”는 뜻이 아닙니다.
LLM 키가 없어도 기술+뉴스 규칙은 동작하는 새 정책입니다. 원본의 LLM 필수 매수 조건을 그대로 유지한 것은 아닙니다.
선택적 LLM에 뉴스를 넣고 그 LLM 점수를 사용한 경우, 같은 뉴스를 직접 점수에 다시 더하지 않습니다.

## 경제사건 추출

| 사건 | 관측하는 문구 예 | 의미와 한계 |
|---|---|---|
| 이익 개선/악화 | 실적 개선, 흑자 전환, record profit / 적자 전환, profit warning | 이익 관련 보도이며 미래 현금흐름으로 환산하지 않습니다 |
| 계약 증가/감소 | 공급계약 체결, 수주 확대 / 계약 해지 | 매출 기회·위험이며 수주액을 순이익으로 취급하지 않습니다 |
| 주주환원 | 배당 확대, 자사주 소각, dividend increase | 환원 사건이며 저평가나 수익 보장은 아닙니다 |
| 운영 위험 | 리콜, 공장 화재, production halt | 비용·공급 위험이며 피해액을 임의 추정하지 않습니다 |

제목 안에서 대상 기업이 등장하는 문장 구간만 점수에 사용합니다. 검색 요약의 다른 기업 감성을 섞지 않습니다.
경쟁사 언급, 우선주 기사, 미래/오래된 기사, 시각 누락, 전망·루머·부인·혼합 감성은 제외하거나 영향 0으로 둡니다.
검색 결과는 보도 내용이며 기사 내용의 진실까지 자동 검증한 것은 아닙니다. 학습된 금융 감성 모델도 아닙니다.

발행 시각과 실제 수집 시각 observed_at을 함께 저장합니다. 당시 수집하지 않은 뉴스를 과거 시점에서 사용하지 않습니다.
기본 48시간을 넘긴 기사는 제외하고 12시간 반감기로 영향을 줄입니다.
GNews 무료 플랜의 12시간 지연은 추가 감쇠(기본 1/2)를 적용합니다. 이는 여러 날에 걸친 보조 신호이며 속보 매매가 아닙니다.
전망/부인 등을 완벽히 이해하거나 기업별 영향을 정확히 분리하는 언어 이해 능력이 있는 것은 아닙니다.

서로 다른 출처 호스트 그룹 2개 이상에서 방향성이 있는 사건이 있어야 조정을 적용합니다.
같은 URL/유사 제목은 제거하고 같은 출처·같은 방향은 한 번만 셉니다.
호스트 그룹은 도메인 기반의 근사치이며 언론사 소유관계나 독립 취재를 보증하지 않습니다.
한국어/영어 번역 기사나 다른 제목의 같은 사건을 완전히 제거하지 못합니다.

## 네이버 이용 조건에 따른 변경

2026-09-20 시행 NAVER API HUB 약관 개정 공지에는 검색 데이터를 AI에 입력하거나 활용하는 제한이 명시되어 있습니다.
검색 결과를 제공하는 목적과 데이터 가공/저장에도 제한이 있어, 이번 자동 판단 경로에서는 네이버 수집·분석·저장을 제외했습니다.
기존에 키가 정상 발급되었다는 사실은 분석 용도 허용의 증거가 아닙니다.
NaverNewsClient의 통신 어댑터 자체는 남겨두었지만 NewsService는 네트워크 호출 전 RESTRICTED 상태를 반환합니다.
LLM 입력·경제사건 계산·분석 저장에서도 naver 공급원을 거부합니다. 과거 저장 자료를 새 판단에 재사용하지 않습니다.

출처: https://www.ncloud.com/support/notice/all/2243

GNews는 영문 기업명으로 검색합니다. 무료 API의 실제 기사 확보량은 종목별로 다를 수 있습니다.
Samsung 약칭도 허용하되 Samsung Display/SDI 등 다른 법인 제목은 보수적으로 제외합니다. 일반 약칭의 회사 귀속을 완벽히 보증하지는 않습니다.
GNews 호출 시작 간격을 2.1초 이상으로 두며, 429가 발생하면 자동 재요청하지 않고 다음 주기의 상태로 남깁니다.
실제 보도가 없으면 임의로 뉴스를 생성하거나 네이버 결과로 우회하지 않습니다.

## 기록과 실행

- app/economic_news.py: 경제사건·근거·반감기·수집시각·중복·출처 기준을 계산합니다.
- app/decision_policy.py: 기준 점수와 뉴스 조정을 합쳐 매수·매도·보유를 정합니다.
- app/engine.py: 위 두 모듈을 실제 매매 결정과 수량 계산 앞에 연결합니다.
- policy_decisions 테이블: 뉴스 미반영/반영 점수와 방향, 근거, 수량, 실행 결과를 함께 기록합니다.
- 기존 decisions/orders/news_reports 테이블도 유지합니다. 필수 위험 입력 누락은 주문 차단입니다.
- order_intents에는 제출 전 의도를 남깁니다. 제출 응답·상태 확인이 불명확하면 UNKNOWN으로 기록하고 사이클을 중단합니다. 재시작 후에도 미확정 의도가 남아 있으면 새 주문을 차단합니다. 자동 대사는 아직 없습니다.

```bash
python -m app.strategy_demo --output data/strategy_demo.json
python -m app.news_cli --provider gnews --symbol 005930 --output data/gnews_news.json
python -m app.main --once --scan-only
```

첫 명령은 합성 점수와 합성 뉴스만 사용하는 정책 시연이며 실제 시장 백테스트가 아닙니다.
두 번째는 GNews 실제 뉴스만 조회하며 팀 코드/LLM 키가 필요 없습니다.
마지막 명령은 AQuA TEAM_CODE를 설정한 뒤 실행해야 하며, 팀 자산 조회와 캔들 조회까지 수행하지만 주문하지 않습니다.

권장 설정:

```dotenv
NEWS_ENABLED=true
NEWS_PROVIDERS=gnews
NEWS_STRATEGY_ENABLED=true
NEWS_USE_IN_LLM=false
NEWS_ALLOW_DELAYED_IN_STRATEGY=true
DRY_RUN=true
ENABLE_TRADING=false
```

현재 정책은 수익률 검증 전인 수업용 실험입니다. 감성 정확도·실제 시점의 뉴스/시세 비교·거래비용을 포함한
전향적 평가가 필요합니다. 테스트 수와 합성 사례 통과를 수익 개선으로 표현하지 않습니다.
미체결 주문 대사·호가 잔량별 예상 체결비용·팀 전체 API 사용량 조율·공휴일 달력은 여전히 미완성입니다.
